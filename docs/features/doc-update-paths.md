## 按部门的文件名别名（4.1.5 四条隐患排查表）

依据业务文档《文档更新检查文件路径》（2026-11-17 版）：多数部门把 `4.1.5` 的三个专业
**合订成一份「部门（级）隐患排查表」**，文件名里没有专业词。这类目录由 seq 29/30/31 共用
（`_named_roots` 判定为共享钉点，不能拿目录名当项名），编号虽能命中钉点目录名，但关键词
`供配电/制冷/智能化` 对不上文件名 → 三项会整项判「未找到」。

修法：`service/doc_update/paths.py` 的 `_DEPT_ITEM_NAMES` 按「公司 × 部门」登记该项的
**真实文件名别名**（`item_names()` 读取），只在部门口径、且只在钉点子树内生效
（`fetch._match_files` 透传给 `match_item`）。别名与 `item.folders` 同权，命中即算、不过关键词闸。

| 部门 | seq 29/30/31（部门级） | seq 32（班组级） |
| --- | --- | --- |
| A1 / A2 / A3 / A5 / A7 / A8 / A9 / A11 / A12 / B1M1 | `部门隐患排查` / `部门级隐患排查`（前缀） | `班组隐患排查` / `班组级隐患排查`（前缀） |
| A10 | 目录名 `供配电部门隐患排查表` / `制冷部门隐患排查表` / `智能化部门隐患排查表` | 目录 `班组隐患排查` |

- **A6 / A18 / B1M2 不配**：A6/A18 专业写在文件名里（`…部门级隐患排查记录表_供配电/_制冷/_智能化`），
  现有「编号 + 关键词」逻辑已正确；B1M2 的 29~31 钉在同一叶子，加别名会把三个专业串成同一份
  （编号 `4.1.5` + 关键词已能消歧，32 在兄弟目录）。
- **A10 登记的是目录别名**：其专业只写在目录名上，业务文档里该部门的文件名注释是复制粘贴
  （三行都写「供配电…」），不可信。
- **不进 `catalog.DocItem.folders`**：那是全局别名，会让所有部门所有专业互相串。
